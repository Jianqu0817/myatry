# 微信版本升级指南

本文说明当上游 [WeChatAgent](https://github.com/sourcepro5/WeChatAgent) 发布支持**新版微信**的发行包时，如何让本项目接入新版本。日常运行不需要本文；版本兼容的权威数据源是 `src/myatry/wechat-versions.json`。

核对日期：2026-10-24。当日上游最新 0.4.0 仍只支持微信 **4.1.10.27**。

## 背景：版本为什么锁死

微信收发链路 = 匹配微信客户端 + WeChatAgent hook（`version.dll`）+ reader。约束有三层：

1. **hook DLL 二进制校验**：0.3.9 的 hook 在 C++ 层拒绝任何 `CoreVersion() != "4.1.10.27"` 的微信。这是硬约束——**上游不发布新 hook，任何新版微信都无法接入**，改本项目配置无用。
2. **运行区脚本校验**：WeChatAgent 自带 `project-config.mjs`、`wechat-account-check.mjs` 等也硬编码版本。
3. **本项目校验**：`wechat_client.check()` 查兼容表（`HOOK_VERSION_MISMATCH`）；本表即第 3 层的唯一数据源。

因此"升级微信"的唯一正确路径是等上游发新包，然后按下文操作。**不要安装比兼容表更新的微信**：链路会直接失效，只能按旧项目 README 的恢复流程降级回来。

## 升级步骤（上游发布新微信支持后）

1. **确认上游声明**：WeChatAgent Releases 页新版本注明"匹配微信 X.Y.ZZ.NN"。记录安装包 SHA256。
2. **准备新运行区**：下载安装包，`Get-FileHash` 校验 SHA256，按发行包说明初始化其数据工作区并安装匹配微信 X.Y.ZZ.NN。**保留旧运行区不删**——这是回退路径。
3. **加表项**：编辑 `src/myatry/wechat-versions.json`，`versions` 数组新增一条：

   ```json
   {
     "wechat_version": "X.Y.ZZ.NN",
     "client_dir": "state/hook/wechat-X.Y.ZZ.NN",
     "wechatagent_runtime": "上游新版本号",
     "integration": "WeChatAgent-1",
     "backend": "wechat-hook",
     "notes": "按上游发行说明填写"
   }
   ```

   旧条目保留（支持多版本共存）。
4. **改指向**：`config/wechatagent.local.toml` 的 `project_dir` 指向新运行区。
5. **验证**：

   ```powershell
   .venv/Scripts/python.exe -m myatry versions        # 新版本应显示"在表内"
   .venv/Scripts/python.exe scripts/wechat_reader.py --config config/wechatagent.local.toml   # 单独终端
   .venv/Scripts/python.exe -m myatry bind
   .venv/Scripts/python.exe -m myatry wechat --offline --observe-only --ui   # 先只收不发
   ```

6. **手抄另一仓库**：MYATRI-AstrBot 项目的 `astrbot_plugin_myatri/wechat-versions.json` 必须与本项目字节一致（`scripts/check_shared.py` 校验）。
7. 稳定后再切 `--live`。回退 = `project_dir` 指回旧运行区。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `HOOK_VERSION_MISMATCH` | 运行 `python -m myatry versions` 看在线 hook 报告的版本；不在表内说明上游 hook 与表不匹配，按上文升级或回退 |
| 微信自动升级了 | 托盘退出 → 从已校验发行组件恢复匹配版本（同旧项目 README 流程）；微信 4.x 会静默自升级，长期建议关闭其自动更新 |
| 上游 hook 版本与微信不匹配 | 上游问题，本项目无法绕过；在兼容表 notes 里如实记录，等待上游修复 |

## 维护约定

- 兼容表是**唯一**允许出现微信版本号的数据源；代码中不得再新增 `4.1.10.27` 之类字面量（测试夹具除外）。
- 两仓的 `wechat-versions.json` 手工保持一致：改一处后手抄另一处，并运行 `scripts/check_shared.py` 校验（AstrBot 项目同名文件在 `astrbot_plugin_myatri/`）。
- 本指南与兼容表同步更新；表中新增版本时在"核对日期"处登记。
